# Localization audit: what is translated and what is not

Languages: Russian (`ru`, default), Kazakh (`kk`), English (`en`). Date of audit: 2026-10-13.
How the system works is described in [localization.md](localization.md).

The interface is fully localized. Educational content is translated **only where translations exist in the
database**: everything seeded with the product has Russian and Kazakh translations, but content that administrators
create or edit later shows the English base text until someone adds its translations (see "Not translated").

## Interface (frontend)

Every user-facing string goes through i18next. Key counts (identical in ru/kk/en, enforced by
`frontend/src/test/i18n.test.ts`, which also fails on empty values, mismatched `{{variables}}` and keys used in the
source but missing from the files):

| Namespace | Keys | Covers |
|---|---:|---|
| common | 199 | actions, states, design-system strings, enum labels, validation, roles, statuses |
| errors | 107 | every API error code |
| auth | 129 | sign-in, registration, recovery, verification, Google, account security settings, API success messages |
| public | 87 | landing, legal pages chrome, 404/500, app shell |
| subscriptions | 33 | plans, features, upgrade prompts |
| dashboard | 113 | dashboard, progress |
| assessment | 216 | assessment, results, competencies |
| learning | 116 | plan, resources, practice |
| account | 64 | onboarding, profile |
| admin | 468 | admin shell, dashboard, analytics, users, user detail, roles, audit labels |
| adminContent | 293 | plans, subscriptions, audit log, settings, content management, AI governance |

Dates, numbers, percentages and currency use `Intl` with `ru-RU`, `kk-KZ`, `en-US`.

## Texts generated by the backend

Translated (60 entries in `backend/app/core/i18n.py`, rendered at read time so they follow the current language):
score explanations, recommendation reasons, competency evidence and tags, resource type and priority labels,
history labels, plan step titles and reflection prompts, in-app notifications, rule-based AI feedback and profile
insights (mock provider and the safe fallback). Emails (verification, password reset) exist in all three languages
and use the account language.

Two English criterion names are used twice with different descriptions ("Persistence", "Insight"); each has one
translation whose description covers both uses.

## Not translated

| What | Why / what happens |
|---|---|
| Content created or edited by administrators after seeding | Shown in English (base text) until translations are entered for it in the admin content editor. Editing the English text of a seeded item does not update its translations automatically. |
| User-generated text: names, open answers, practice submissions, reflections, profile fields, admin notes and reasons | Shown as written. |
| Feedback and insights written by a real AI model (`MOCK_AI=false`) | Generated in the request language (the prompt asks for it) and stored as generated; they don't switch when the user changes language later. Rule-based feedback does switch. |
| AI prompt templates (admin → AI) | Kept in English on purpose; the response language is added per request. |
| Plan names Free / Pro / Premium, brand "Isker", "EntreComp", "SCAMPER", "Crazy 8s" | Proper names. |
| Machine values: IDs, codes, slugs, enum values, permission keys, audit action codes, API field names | Never translated. Admin screens show a translated label next to the raw code where it helps. |
| API `message` fields | English fallback only; the UI shows the translation of `error.code` / `message.code`. |
| Server logs, OpenAPI documentation (`/api/docs`), developer docs | English. |
| User-agent strings in the session list | Browser and OS names are product names; the surrounding text is translated. |

## Verification

- `frontend/src/test/i18n.test.ts` — key parity, no empty values, same variables, keys used in source exist,
  plural forms work in each language.
- `backend/tests/test_localization.py` — `Accept-Language` parsing, content in ru/kk/en with unchanged ids,
  localized reads never overwrite base text, admin editors see base text, Russian open answers scored with Russian
  keywords, generated texts/insights/notifications/plan steps per language, saved language preference, emails in the
  account language, stable error codes, generic password-reset response.
