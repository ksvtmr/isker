# Database

PostgreSQL 16, managed with **SQLAlchemy 2** models (`backend/app/models/`) and **Alembic** migrations
(`backend/alembic/versions/`). JSON is used only for genuinely unstructured payloads (rubric definitions, AI outputs
and evidence lists, audit and subscription-event details). The table reference below is generated by
`backend/scripts/gen_docs.py`.

## Entity overview

```
users 1─1 user_profiles          users 1─* user_goals *─1 goal_definitions 1─* goal_competency_weights *─1 competencies
competency_areas 1─* competencies          competency_levels (5 bands)
assessments 1─* questions 1─* question_options
                questions 1─* question_competencies *─1 competencies   (weight)
users 1─* assessment_attempts 1─* answers *─1 questions / question_options
          assessment_attempts 1─* competency_scores   (immutable history, one row per competency per attempt)
          assessment_attempts 1─* competency_gaps     (target, gap, band, priority components, rank)
          assessment_attempts 1─1 progress_snapshots  (overall + area scores at that moment)
          assessment_attempts 1─0..1 reassessments    (links to the previous attempt)
competency_gaps 1─* recommendations *─1 learning_resources / practical_tasks / goal_definitions
recommendations 1─4 learning_activities  (learn → practice → reflect → reassess)

Access control and accounts
roles 1─* role_permissions *─1 permissions        users 1─* user_roles *─1 roles   (granted_by → users)
users 1─* user_sessions                           (JWT jti = session id; revocable)
users 1─* email_verification_tokens / password_reset_tokens   (SHA-256 hashes only, single use, expiring)
audit_logs                                        (append-only; actor_id/target_id are plain ids, no FK)

Plans and subscriptions
subscription_plans 1─* plan_entitlements          (feature_key, enabled, limit_value)
users 1─* user_subscriptions *─1 subscription_plans
user_subscriptions 1─* subscription_events        (who/what/why/source for every change)
payment_webhook_events                            (unique provider + event_id → idempotency)
```

## Integrity rules
- Every foreign key is explicit with an `ON DELETE` policy (user data cascades; catalogue rows are `RESTRICT`).
- Unique constraints: one answer per question per attempt; one score/gap per competency per attempt; one
  progress row per user and resource; one submission per user and task; one role per user once; one entitlement row
  per plan and feature; one processed webhook per provider and event id.
- CHECK constraints: scores 0–100, weights 0–1, progress 0–100, prices and limits ≥ 0, and every enum column
  (stored as VARCHAR + CHECK so migrations stay portable).
- **History is never overwritten.** Each completed attempt writes new `competency_scores`, `competency_gaps` and a
  `progress_snapshot`; subscription changes append `subscription_events`.
- **Audit log is append-only.** On PostgreSQL a trigger (`audit_logs_append_only`) rejects UPDATE, DELETE and
  TRUNCATE. Audit rows store ids, not emails, so they survive account deletion without keeping personal data.
- Passwords are bcrypt hashes; verification/reset tokens are stored as SHA-256 hashes; no payment-card data exists.

## Migrations
```bash
cd backend
pg_dump -Fc "$DATABASE_URL" > backup-$(date +%F).dump    # always back up before upgrading production
alembic upgrade head                                   # apply
alembic revision --autogenerate -m "describe change"   # create
alembic check                                          # verify models and migrations match
```

`0002` (RBAC, sessions, plans, audit) migrates data in place: `users.role=admin` → `super_admin` role, every user
gets the `user` role, `is_active=false` → `status=deactivated`, and audit columns are renamed with values copied.
It drops `users.role`, `users.is_active` (after copying) and `revoked_tokens` (only held ids of expired/logged-out
JWTs; everyone signs in again). `alembic downgrade 0001` maps the data back. Restore from the dump if anything goes
wrong: `pg_restore --clean -d "$DATABASE_URL" backup.dump`.
